## Copie a partir daqui

Objetivo: o usuário consegue criar a pasta da história e validar as fichas.

Contexto: a pasta templates/ contém o que o init deve copiar. O formato da ficha está no CLAUDE.md, seção "Formato da ficha".

Parte 1 — núcleo (src/core), testes primeiro:
1. Função que separa frontmatter YAML do corpo de um texto markdown. Casos: arquivo sem frontmatter, frontmatter mal fechado, YAML inválido. Cada caso devolve um erro descritivo, não lança exceção crua.
2. Schema Zod da ficha conforme o CLAUDE.md. aliases e aparece_em viram lista vazia quando ausentes.
3. Função de validação de uma pasta já lida (recebe uma lista de { caminho, conteúdo }, não lê disco) que devolve uma lista de problemas, cada um com: caminho, campo, mensagem, gravidade (erro ou aviso). Regras:
   - erro: frontmatter inválido, campo obrigatório ausente, tipo fora da lista, id diferente do nome do arquivo, id fora do padrão minúsculas-e-hífen, id duplicado;
   - erro: biblia.md ou estado.md ausentes na raiz;
   - aviso: o mesmo nome ou alias aparece em duas fichas diferentes (vai atrapalhar o pack no M2), comparando sem diferenciar maiúsculas nem acentos;
   - aviso: ficha numa pasta que não bate com o tipo (ex.: tipo lugar dentro de fichas/personagens).

Parte 2 — comandos (src/cli):
4. init <pasta>: copia templates/ para a pasta indicada. Se a pasta existir e não estiver vazia, recusa com mensagem clara e não altera nada. No fim, imprime os próximos passos (colar a bíblia, criar as primeiras fichas, rodar check).
5. check [pasta]: lê a pasta (padrão: a atual), chama a validação do núcleo e imprime os problemas agrupados por arquivo. Código de saída 1 se houver qualquer erro, 0 se só houver avisos ou nada. Se estiver tudo certo, diz quantas fichas foram validadas.

Testes:
- fixtures em tests/fixtures/: uma pasta válida com 3 ou 4 fichas inventadas e uma pasta para cada tipo de erro e de aviso;
- init numa pasta nova cria a estrutura; init numa pasta com arquivos recusa e não altera nada;
- check devolve o código de saída certo em cada fixture.

Critério de aceite: rodo init numa pasta nova, crio uma ficha com erro de propósito, e o check me diz exatamente o arquivo, o campo e como consertar.

Não faça: o comando pack, nenhuma dependência além de yaml e zod (registre as duas em docs/DECISOES.md).
